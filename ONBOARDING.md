# ts-artifacts Onboarding Guide

## Overview

- Monorepo for TypeScript packages targeting the **Artifacts MMO** game API.
- Written against **API version 2.2.0** (last updated October 2024).
- Runtime: **Bun 1.3.11**. Language: **TypeScript 5.6.2** (strict, ESNext, ESM-only).
- Core deliverable: `@trey.turner/artifacts-api-client` — a typed, promise-based API client published to npm.

---

## Quick Start

```sh
# Install dependencies (from monorepo root)
bun install

# Build all packages
bun run build

# Run linting + formatting + type checking across all packages
bun run check

# Auto-fix lint/format issues
bun run check:fix

# Run tests for a specific package
cd packages/api-client && bun test

# Clean everything (build artifacts + node_modules + lockfile)
bun run clean

# Watch mode (rebuild on change)
bun run watch
```

## `api-client` Architecture (the core package)

### Entry point (`src/index.ts`)

The `ArtifactsApi` class is the public API surface. It composes method groups by spreading plain-object modules and binding `this.client` (the `ArtifactsApi` instance) into each group via a `HasClient` pattern. This is **not** class inheritance — it's functional composition using `this`-bound free functions.

### Method group organization

```text
ArtifactsApi
├── config             — Config object (mutable after construction)
├── state              — In-memory game/world/account state cache
├── account            — Account management (no cooldown)
│   ├── bank           — Account bank queries
│   ├── characters     — Character CRUD + logs
│   ├── create()       — Create game account
│   ├── changePassword()
│   └── getToken()     — Basic-auth → bearer token
├── bank               — Bank actions (deposit/withdraw, cooldown applies)
├── craft              — Crafting actions
├── exchange           — Grand Exchange buy/sell
├── fight              — Combat (once / continuously)
├── gather             — Resource gathering (once / continuously)
├── info               — Read-only game data (no auth, no cooldown)
│   ├── achievements, characters, exchangeItems, items
│   ├── maps, meta, monsters, resources, tasks
├── items              — Item management (equip/unequip/discard/recycle)
├── move               — Movement (to coordinates or by content type)
└── tasks              — Task system (accept/cancel/complete/exchange/trade)
```

### Type system (`src/types.ts`)

All request/response types are derived from `src/lib/api.generated.ts` (auto-generated by `openapi-typescript` from `https://api.artifactsmmo.com/openapi.json`). Manual aliases in `types.ts` give them friendly names and re-export them. Key custom types:

| Type          | Purpose                                                       |
|---------------|---------------------------------------------------------------|
| `Config`      | API base URL, auth credentials, character name, logging prefs |
| `State`       | In-memory cache of bulk-fetched game data                     |
| `HasClient`   | `{ client: ArtifactsApi }` — injected into every method group |
| `CallOptions` | Shared options bag for HTTP calls (path, method, body, query) |
| `DataPage`    | Paginated response wrapper (data array + paging metadata)     |
| `DataPageReq` | `{ page?: number; size?: number }` — pagination params        |

### HTTP layer (`src/http.ts`)

Three call patterns, all built on native `fetch`:

| Function          | Method | Purpose                                                                                          |
|-------------------|--------|--------------------------------------------------------------------------------------------------|
| `actionCall<T>()` | POST   | Actions that return data + cooldown; automatically waits for cooldown to expire before resolving |
| `infoCall<T>()`   | GET    | Simple GET calls returning data without cooldown                                                 |
| `pageCall<T>()`   | GET    | Paginated GET calls; used with `handlePaging()` to auto-fetch all pages                          |

Supporting functions: `request()` (raw fetch wrapper), `handleResponse()` (parses + logs + handles cooldown), `handlePaging()` (iterates pages and accumulates results).

### Authentication (`src/config.ts`)

Two auth modes, resolved from environment variables or constructor options:

1. **Bearer token** — `ARTIFACTS_API_TOKEN` env var, set directly via `config.apiToken`.
2. **Username/password** — `ARTIFACTS_USERNAME` / `ARTIFACTS_PASSWORD` env vars; the client auto-acquires a bearer token on the first authenticated call via `setToken()`.

### State management (`src/index.ts`)

| Method              | Populates                                                     |
|---------------------|---------------------------------------------------------------|
| `syncGameInfo()`    | Items, monsters, resources, tasks, task rewards, achievements |
| `syncWorldInfo()`   | Maps, active events, Grand Exchange items                     |
| `syncAccountInfo()` | Characters, bank items, bank details                          |
| `sync()`            | All of the above (parallel)                                   |

All state is purely in-memory on the `state` property.

### Logging (`src/util.ts`)

Timestamped console logging with caller name detection via stack traces. Configurable via environment variables:

- `ARTIFACTS_LOG_HTTP_REQUESTS` — log outgoing requests
- `ARTIFACTS_LOG_HTTP_RESPONSES` — log incoming responses
- `ARTIFACTS_HIDE_CHARACTER_IN_RESPONSE` — redact character data in logs
- `ARTIFACTS_HIDE_COOLDOWN_IN_RESPONSE` — hide cooldown info in logs

## Code Generation Pipeline

Two independent pipelines, both sourcing from `https://api.artifactsmmo.com/openapi.json`:

### 1. `api-client` types

```sh
cd packages/api-client
bun run generate
```

Runs `openapi-typescript` → produces `src/lib/api.generated.ts` (a single large file of TS interfaces mapping every path, operation, component, and schema).

### 2. `mocks-counterfact` mock server

```sh
cd packages/mocks-counterfact
bun run generate    # Generate types + route handlers from OpenAPI spec
bun run open        # Launch Counterfact GUI
bun run repl        # Start REPL + watch + mock server
bun run watch       # Start mock server + file watcher
```

Runs `counterfact -g` → produces both `src/types/` (per-route type files) and `src/routes/` (per-route handler stubs that return `$.response[200].random()`).

### When upgrading the API version

Both `generate` scripts must be re-run against the new OpenAPI spec URL (or a local copy). The generated output in `api-client` will change `api.generated.ts`, which will cascade type errors into `types.ts` and every module that references changed schemas. The `mocks-counterfact` output will regenerate route types and may add/remove route handler files.

## Testing

- **Test runner:** Bun's built-in test runner (`bun test`).
- **Test location:** `packages/*/test/` directories, each with its own `tsconfig.json` referencing the `src` project.
- **Test types present in `api-client`:**
  - **E2E tests** (`test/e2e/`): Hit the real production API. Tests for info endpoints (items, server status, leaderboard, events), account operations (anonymous access, auto-token retrieval, bank queries). Configured with 15-second timeout.
  - **Mock/unit tests** (`test/e2e/state.test.ts`): Uses `bun-bagel` to mock HTTP and test state sync orchestration.
- **Validation helpers** (`test/validate.ts`): Shape-validation functions for response objects (serverStatus, map, item, leaderboard entry, etc.) — useful for verifying API compatibility after upgrades.
- **No tests exist yet** for `cli`, `mocks-counterfact`, or `sandbox`.

## CI/CD Pipeline

Three GitHub Actions workflows in `.github/workflows/`:

### 1. `commitlint.yaml`

Runs on push & PR. Validates commit messages via `wagoid/commitlint-github-action@v6`.

### 2. `test-build.yaml`

Runs on PR & `workflow_call`. Matrix-tests packages listed in `vars.TESTABLE_PKGS` and matrix-builds packages listed in `vars.BUILDABLE_PKGS`. Uploads `dist/` as artifacts.

### 3. `release-publish.yaml`

Runs on push to `main`. Calls test-build first, then runs `release-please` (separate PRs per package), then npm-publishes any released packages from `vars.PUBLISHABLE_PKGS` with provenance.

### Required GitHub configuration

**Repository variables:** `TESTABLE_PKGS`, `BUILDABLE_PKGS`, `PUBLISHABLE_PKGS` (JSON arrays of package directory names).

**Repository secrets:** `ARTIFACTS_API_TOKEN`, `ARTIFACTS_USERNAME`, `ARTIFACTS_PASSWORD`, `ARTIFACTS_CHARACTER`, `RELEASE_PLEASE_TOKEN`, `NPM_TOKEN`.

## Conventions & Standards

- **Commits:** Conventional Commits enforced by commitlint (locally via Husky `commit-msg` hook, in CI via GitHub Action). Types: `feat`, `fix`, `perf`, `revert`, `docs`, `style`, `chore`, `refactor`, `test`, `build`, `ci`.
- **Formatting:** Biome — 2-space indent, 120 char line width, LF line endings, semicolons always, trailing commas always. `dist/` directories ignored.
- **Linting:** Biome — errors on unused variables and unused imports (no auto-fix for these). Overrides relax rules for generated files (`mocks-counterfact/src/types.ts`, `api-client` equivalent).
- **TypeScript:** Strict mode, `noUncheckedIndexedAccess`, `verbatimModuleSyntax`, `bun-types` ambient types.
- **Release:** `release-please` with `node-workspace` plugin, separate PRs per package, semver with `v` prefix in tags. Pre-1.0 packages get patch bumps for minor changes.

## Patterns for Adding/Modifying Endpoints

When a new API endpoint needs to be added:

1. **Regenerate types:** Run `bun run generate` in `packages/api-client/` to update `src/lib/api.generated.ts`.
2. **Add type aliases:** In `src/types.ts`, add request/response type aliases referencing the new `components["schemas"]` or `operations` entries.
3. **Create or update a module:** Follow the existing pattern in `src/actions/` or `src/info/`:
   - Export a const object of named functions.
   - Each function takes `this: HasClient` and uses `actionCall`, `infoCall`, or `pageCall`/`handlePaging`.
   - Path tokens use `{name}` for character name.
4. **Wire into ArtifactsApi:** In `src/index.ts`, import the module and spread it into the appropriate property with `{ client: this, ...module }`.
5. **Update the type declaration** on the class property to include `HasClient & typeof module`.
6. **Optionally regenerate mocks:** Run `bun run generate` in `packages/mocks-counterfact/` for updated mock routes.
